## 1. 背景与目标

第5组负责系统协调层，核心目标是将第1/2/3/4组模块串联起来，并提供安全检查、审计追踪、知识检索能力，形成可验收的端到端执行闭环。

### 1.1 目标

1. 建立统一编排入口，完成跨组模块调度。
2. 建立四层安全机制，拦截危险操作和高风险访问。
3. 建立可持久化的审计与轨迹知识库。
4. 支持联调、演示与验收复现。

### 1.2 非目标

1. 不负责第1组意图识别模型训练。
2. 不负责第2组控件检测算法实现细节。
3. 不负责第3组GUI动作执行底层实现。
4. 不负责第4组工具业务逻辑细节。

---

## 2. 架构分析

第5组位于系统协调层，定位为“流程编排中枢 + 安全闸门 + 知识沉淀中心”。

> 【截图占位-01】系统总体架构图（第1组~第5组调用关系图）

### 2.1 逻辑分层

1. 输入层：接收第1组 `intent_json`。
2. 安全层：`SecuritySandbox` 执行四层安全检查。
3. 编排层：`SystemCoordinator` 调度第2/3/4组。
4. 持久层：`AuditLogger` + `RAGKnowledgeBase` 记录与检索。
5. 输出层：统一返回 `orchestrate_result`。

### 2.2 核心模块

- `coordinator/system_coordinator.py`
- `security/security_sandbox.py`
- `knowledge/rag_kb.py`
- `knowledge/trace_store.py`
- `audit/audit_logger.py`

## 3. 接口契约

### 3.1 输入接口（第1组 -> 第5组）

`IntentJSON`（`contracts/schemas.py`）：

```json
{
  "trace_id": "string",
  "action": "string",
  "target": "string",
  "params": {},
  "raw_text": "string"
}
```

### 3.2 安全检查输出（第5组内部/对外）

`CheckJSON`：

```json
{
  "approved": true,
  "risk_level": "low|medium|high|critical",
  "reason": null,
  "matched_policy": "SEC-001"
}
```

### 3.3 最终编排输出

`OrchestrateResult`：

```json
{
  "success": true,
  "trace_id": "string",
  "stage": "security|planning|execution|tool_call|completed",
  "result": {},
  "error": null,
  "latency_ms": 123.45
}
```

### 3.4 错误码（核心）

- `E1001`：安全策略拒绝（危险操作/受保护路径）
- `E1002`：路径穿越攻击检测
- `E2001`：规划模块不可用
- `E3001`：执行模块不可用
- `E4001`：工具模块不可用
- `E5001`：输入校验失败
- `E5002`：模块调用超时
- `E5003`：未知内部错误

## 4. 模块设计

### 4.1 SystemCoordinator

职责：
1. 注册并管理 group2/group3/group4 模块。
2. 执行“校验->安全->规划->执行->工具->入库”主流程。
3. 统一错误处理、超时控制、审计写入。
4. 默认写入持久化文件：
   - `group5/data/rag_traces.json`
   - `group5/data/audit_events.jsonl`

> 【截图占位-02】`SystemCoordinator.orchestrate()` 主流程代码截图

### 4.2 SecuritySandbox（四层安全）

四层检查顺序：
1. 权限检查（策略命中）
2. 沙箱执行检查（写目录约束）
3. 签名验证（HMAC，带签名时强校验）
4. 隐私保护（敏感信息访问拦截）

> 【截图占位-03】`SecuritySandbox` 四层安全逻辑代码截图

### 4.3 RAGKnowledgeBase

1. 维护执行轨迹 `TraceRecord`。
2. 支持查询、统计、按 `trace_id` 检索。
3. `trace_store.py` 支持 numpy 与纯Python降级检索。

> 【截图占位-04】RAG检索结果示例截图（命令行输出）

### 4.4 AuditLogger

1. 异步队列记录审计事件。
2. 支持按 `trace_id` 检索。
3. 支持落盘，便于追溯和验收。

> 【截图占位-05】审计日志文件样例截图（`audit_events.jsonl`）

## 5. 流程图

### 5.1 端到端时序（文字版）

1. 用户输入自然语言。
2. 第1组解析并输出 `intent_json`。
3. 第5组执行安全检查。
4. 安全通过后调用第2组生成计划。
5. 调用第3组执行计划。
6. 需要时调用第4组工具。
7. 写审计与RAG并返回统一结果。

> 【截图占位-06】端到端时序图（建议 draw.io / mermaid 导出）

### 5.2 安全拦截分支

1. 命中危险命令 -> 返回 `E1001`。
2. 命中路径穿越 -> 返回 `E1002`。
3. 拦截事件写审计并写失败轨迹。

> 【截图占位-07】安全拦截流程图

## 7. 风险评估与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 其他组接口变更 | 联调失败 | 接口版本管理 + mock兼容层 |
| 安全策略过严误拦截 | 正常任务失败 | 分级策略 + 白名单调优 |
| 依赖缺失（如 numpy） | 测试/运行失败 | 纯Python降级策略 + README说明 |
| 演示环境差异 | 结果不一致 | 提供 Linux/macOS/Windows 运行指南 |
